### 2. `image_size` khớp tỉ lệ ảnh control

Thêm 2 hàm trong `registry.ts` (sau `stylePrompt`, dòng ~188):

```ts
export function scaleToMaxSide(w: number, h: number, max: number): { width: number; height: number } {
  const long = Math.max(w, h);
  const scale = long > max ? max / long : 1;
  const round8 = (n: number) => Math.max(8, Math.round((n * scale) / 8) * 8);
  return { width: round8(w), height: round8(h) };
}

async function controlImageSize(url: string): Promise<{ width: number; height: number } | undefined> {
  try {
    const img = await loadImage(url);        // lib/imaging.ts — đã có sẵn, tái dùng
    const w = img.naturalWidth || img.width;
    const h = img.naturalHeight || img.height;
    if (!w || !h) return undefined;
    return scaleToMaxSide(w, h, 1024);
  } catch {
    return undefined;                          // đọc thất bại → KHÔNG throw, không chặn job
  }
}
```

Gắn vào cả 3 node control, ngay trước `aiImage(...)`:

```ts
const image_size = await controlImageSize(String(inputs.image.value));
// ...trong object input gửi job:
...(image_size ? { image_size } : {}),
```

`round8` làm tròn về bội số 8 (yêu cầu phổ biến của model diffusion khi nhận width/height tuỳ
ý) — chọn bội-8 vì đây là mức an toàn tối thiểu chung của họ model diffusion, KHÔNG xác minh được
với model cụ thể `flux-pro/v1/canny`/`depth` vì ràng buộc phiếu cấm chạy job thật (không dev
server/API) — ghi rõ giả định này để phiên sau biết đây là suy luận hợp lý, chưa phải số đo
[T6].

## ③ Đọc thất bại → không chặn job (item ④.2 của phiếu)

`controlImageSize()` bọc `try/catch` quanh toàn bộ `loadImage()` + đọc `naturalWidth/Height`.
Bất kỳ lỗi nào (URL hết hạn, chặn CORS, ảnh 0×0…) → trả `undefined` → object input dùng spread
`...(image_size ? { image_size } : {})` nên field `image_size` **biến mất hoàn toàn** khỏi
request thay vì gửi `undefined`/`null` — đúng hành vi cũ (fal tự chọn `landscape_4_3` như trước
khi có fix), không có field lạ làm job lỗi.

   căn cứ (cùng họ model FLUX Pro Canny/Depth), phiếu không có dữ liệu buộc phải khác nhau.

   job thật thật sự chạy qua fal (ràng buộc cấm dev server/API trong phiên này). Nếu job thật
   sau này báo lỗi kích thước, đây là chỗ đầu tiên cần soát.

   dòng test hiện diện nhưng gãy; đã verify logic bằng cách khác (mục ⑤) và ghi rõ giới hạn hạ
   tầng test hiện tại (không phải bug của lần sửa này).
4. **Không đổi styleTransfer/staging** — 2 node này không set `guidance_scale`, không dính bệnh
