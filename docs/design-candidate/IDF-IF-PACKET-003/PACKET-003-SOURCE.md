## Competitive parity — outcome, not feature count

IF must meet or surpass the professional outcome of relevant competitor workflows in every committed task family. It does NOT promise to clone every feature of every competitor or copy their UI.

For each task family, Research creates a `Capability Parity Card`:

`user job → incumbent tools/workflow → required professional output/quality → time/steps/friction → IF mechanism → proof scenario → gaps → defer/omit rationale`.

Compare task outcome, editability, precision, interoperability, provenance, reliability, performance, accessibility, recovery and time-to-result—not marketing feature lists. A simplified IF flow is accepted only when it preserves or improves required outcome quality and leaves a clear path to expert control.

Rules:

- Learn mechanism and failure boundaries, never copy competitor skin, naming or information architecture.
- “AI faster” is not parity: it needs editable output, provenance, deterministic validation where applicable, compare/undo and export/reopen proof.
- Do not hide professional controls permanently. Use Quick → Guided → Deep so novice flow is simple while expert depth remains available.
- A capability may be `defer` only with an explicit user-job impact and a workable interoperability/fallback path.
- No blanket claim of competitor parity until scenario evidence proves it task family by task family.

## Intent-driven 2D and 3D — professional compression

IF must not make practitioners learn a generic CAD/3D application before they can do their work. Its primary workflow is `brief/intent → parameters + constraints → editable 2D/3D proposal → professional refinement`, while direct drawing/modeling remains available for expert correction.

### 2D Brief-to-Plan

Create a structured `Design Brief / Parametric Sheet` that can capture: project/site, space type, users/activities, area and dimensions, adjacency/circulation, required furniture/equipment, codes/clearances, budget/priority, material/brand preference, references/story/Design DNA candidate and explicit unknowns.

The engine maps this into named parameters, constraints and a proposed plan—never hidden geometry. Each generated line/object must remain editable and explainable: source brief/reference, units, constraint, confidence, affected space and undo path. Reference-image line extraction is only a candidate/overlay; it is not survey truth, dimensions or permission to copy a design.

### 3D Guided Professional Control

Compress complex modeling into comprehensible controls without destroying depth:

`space shell → component package → layout/constraints → material → light → camera → render/present`.

Quick controls express professional intent (room type, furniture family, clearance, finish, lighting mood, view) rather than raw software jargon. Guided mode reveals dependencies and previews impact. Deep mode exposes geometry, transforms, material/PBR, lights, camera, layers, snapping, units, constraints and assemblies for expert work.

Every simplified control resolves to inspectable parameters/objects and preserves direct editing, version, compare, undo and export. Never claim professional equivalence until real tasks prove accuracy, editability, recovery and time-to-result against the manual workflow.

## Resource Factory and IDFC rule

Create a read/write dogfood lane that uses IF itself to import/create/apply/edit/export/reopen resources.

All reusable components, templates, technical packs and library resources use the existing `.idfc` package contract. Do not create competing CAD/3D/material/present package extensions; inspect current `.idfc` contract before extending it and preserve compatibility.

One `component_id` may contain 2D block/layer/anchors/dimensions, 3D parametric geometry/mesh/proxy, material slots/PBR, assembly/hardware, details/elevation/section, BOQ/procurement, presentation metadata and stage representations.

Repeated structure rule: a four-leg chair has FrontLeg Definition ×2 and RearLeg Definition ×2 as instances/mirror/pattern, not copied geometry or duplicated BOM records. 2D/3D/technical/BOQ all resolve to the same component/part identity.

Before a component family: research typology, purpose, ergonomic/dimension rules, variants, assembly, clearance, symbol convention, material, source/license and use cases. Each package then publishes a Usage Guide for Concept, 2D, 3D, Technical/BOQ, Present, limitations and truth level.

Resource scopes are strictly `Global Core / Studio-Tenant / Project / Candidate-Quarantine`; TTT/customer/vendor assets never become global merely by being available locally.

## Anti-drift execution mechanics

Every task uses:

`Task ID · plane · owner · status · goal · in scope · forbidden scope · dependencies · evidence · rollback · Smartboard IDs`.

Only states:
`READY → CLAIMED → RUNNING → REVIEW → DONE` or `BLOCKED`.

Specialists return a single Research-to-Spec Packet:

`observed evidence · 2–3 options · recommendation · acceptance criteria · scope not touched · risks/dependencies · rollback · proof plan`.

Integrate in small explicit commits; never stage broad dirty work. Preserve candidates and old routes behind flags/migrations until runtime parity. Do not open a new total audit unless risk or stale/conflicting evidence requires it; use narrow delta audits and capability proof cards when a core is uncertain, then perform a release audit after slices prove out.
